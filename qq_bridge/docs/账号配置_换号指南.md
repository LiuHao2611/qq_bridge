# qq_bridge 账号配置与换号指南

> 权威规则见 `AGENTS.md` 规则表「账号不得硬编码」。本文件只讲**怎么换号**。
> 最后更新：2026-11-10。

## 一、单一真相源：`.env`

**所有账号只在项目根目录 `.env` 配置一次**，程序代码、脚本、compose、测试夹具里一律不得写死真实 QQ 号 / 群号。`.env` 已被 `.gitignore` 排除，不入库。

| 变量 | 含义 | 谁在跑 | 换号是否要改 |
|---|---|---|---|
| `BOT_UIN` | **机器人登录号**（唯一允许登录 NapCat 的 QQ） | compose → 容器 `ACCOUNT` → `qq -q $ACCOUNT` | ✅ 换机器人号必改 |
| `BOT_OWNER_QQ` | 主人 / 指挥号（逗号分隔多个） | `config.py::Config.BOT_OWNER_QQ` | 换主人号才改 |
| `PRIVATE_WHITELIST` | 私聊白名单（逗号分隔） | `config.py::Config.PRIVATE_WHITELIST` | 视情况 |
| `GROUP_WHITELIST` | 监听群白名单（逗号分隔） | `config.py::Config.GROUP_WHITELIST` + `tools/check_bridge_sanity.py` P3 | 换群才改 |
| `USER_BLACKLIST` | 用户黑名单（逗号分隔） | `config.py::Config.USER_BLACKLIST` | 视情况 |
| `VIDEO_PARSE_OWNERS` | 允许触发视频解析的 QQ（逗号分隔） | 视频解析模块 | 换主人号才改 |
| `OFFICIAL_APPID` / `OFFICIAL_SECRET` | QQ 官方机器人通道（默认关闭） | `bot.py::_official_bots()` | 仅启用官方通道时改 |

`.env.example` 是配置模板，列出了全部账号变量的**空占位**；新环境从它复制为 `.env` 后填写。

## 二、换机器人登录号（最常发生）的标准步骤

1. 编辑 `.env`，只改一行：`BOT_UIN=<新机器人 QQ 号>`。
   - 保持 `BOT_OWNER_QQ`（主人指挥号）与登录号分离，**严禁用主人大号登录 NapCat**。
2. 重建 NapCat 容器，让新的 `ACCOUNT` 生效：
   ```powershell
   .\start_all.ps1
   # 或首次/需要重建时：
   docker compose -f docker-compose.napcat.yml up -d --build
   ```
   两个启动脚本都会先从 `.env` 读 `BOT_UIN` 导出到 compose 进程环境，`start_all.ps1` 传的 `--env-file data\compose.env` 不会把它遮掉。
3. 按 `scripts/qq_login_qr.py` 导出的二维码用**新号扫码**登录（`docker/qqbridge_no_autologin.py` 刻意禁用了自动重登，掉登录后需人工扫码，这是防封号铁律）。
4. 复核：`/api/qq/status` 的 `self_id`、`logs/qq_conn_events.log` 的 ATTACH 记录都应是新号。

> 为什么不用改 compose？`docker-compose.napcat.yml` 里 `ACCOUNT: ${BOT_UIN:?...}` 是插值变量，缺 `BOT_UIN` 会**立即报错**（不会静默拿空号去登录，那正是高频重登封号的诱因）。

## 三、换主人号 / 群 / 白名单

这些是 `config.py` 运行期读的环境变量，`core=false`（热生效）的改完 `.env` 后可在设置页保存或直接重启 bridge；`BOT_OWNER_QQ` / 各白名单改动**不需要重建 NapCat 容器**。

## 四、防回归

`python tools/check_no_hardcoded_qq.py` 扫描生产代码 / 脚本 / compose / 测试夹具，发现已知真实号或「白名单群里写死 10 位 QQ」即 `exit 1`；`--selftest` 注入历史硬编码反例验证门禁本身有效。注释里的历史事故号（封号复盘）与 `docs/`、`AGENTS.md`、`README.md` 的历史记录属于证据，**豁免**。
