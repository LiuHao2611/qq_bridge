# 主题编辑器·文字样式功能设计文档

> 版本 v1.0 ｜ 2026-09-15 ｜ 状态：设计定稿，随本文档同批次实现
> 关联模块：`qq_bridge/src/plugins/qq_bridge/pic/`（fonts.py / canvas.py / theme.py / themes_store.py / editor.py / editor_page.html）

---

## 1. 背景与目标

用户诉求（原话归纳）：
> 文字编辑加多几个样式：**加粗、斜体、划线（下划线/删除线）、描边、描边颜色，把 Word 的那一套搬过来，最好能加上字体**。

现状：主题只控制**颜色**（title/body/sub/badge_text 等 19 个色值），字形样式写死在代码里（标题粗、正文常规），用户无法调整，更没有描边/字体选择。

目标：把 Word 的字符样式模型（B/I/U/S + 描边 + 字体）搬进主题编辑器，按**文本角色**独立配置，Pillow 渲染所见即所得。

**不在本期范围**（明确不做，防蔓延）：
- 富文本混排（同一段文字里部分字加粗）——Word 的 run-level 样式，Pillow 需逐字测量拼接，成本高收益低，本期做到**角色级**（标题/正文/次要/徽章各自一套）。
- 行距/字距调整、竖排、渐变文字。
- 在线字体下载（涉及版权，只用本机已有字体 + 用户自放字体目录）。

## 2. 调研结论（2026-09-15 联网核实）

### 2.1 Pillow 能力（官方文档 12.3.0，pillow.readthedocs.io）

| 能力 | API | 最低版本 | 结论 |
|---|---|---|---|
| 文字描边 | `draw.text(..., stroke_width=N, stroke_fill=color)` | **6.2.0** | ✅ 原生，直接用 |
| 下划线/删除线 | 无原生，用 `draw.textlength()`（≥8.0）量宽 + `draw.line()` 画线 | 8.0.0 | ✅ 标准做法 |
| 伪粗体 | 有粗体变体字体用变体；否则 `stroke_width=1~2, stroke_fill=同色` | 6.2.0 | ✅ 双路兜底 |
| 斜体 | **无原生**。优先找 Italic 变体字体；否则把文字画到临时图层做仿射剪切（AFFINE `(1, k, -k·h, 0, 1, 0)`，k≈0.2） | — | ✅ 双路兜底 |
| 文本测宽/包围盒 | `textlength()` / `textbbox()` / `anchor` | 8.0.0 | ✅ 划线定位用 |
| 字体族元数据 | `ImageFont.truetype(path).getname() → (family, style)` | — | ✅ 扫描系统字体用 |

当前环境 Pillow 为新版（6.2.0 的功能全部可用），`direction/features` 需要 libraqm，**不使用**（中文场景不需要）。

### 2.2 成熟案例借鉴

| 来源 | 借鉴 | 规避 |
|---|---|---|
| Word / CSS `font` 模型 | 字符样式 = 粗体/斜体/下划线/删除线 + 描边（CSS -webkit-text-stroke）+ 字体族 | run 级混排（本期不做，见 §1） |

## 3. 数据模型

### 3.1 设计原则

- **角色级**而非全局：标题/正文/次要文字/徽章文字 4 个角色各一套样式（标题常要粗体、正文不要——全局一套不够用）。
- **放 layout 而非 colors**：颜色表（THEME_FIELDS）有「缺一不可」的严格校验且会动到预设填充逻辑；形状类字段（layout）允许缺失即默认，**老主题 JSON 零迁移**。
- 描边颜色不能复用 layout 的 `str` 类型（该类型按资源文件名白名单校验，`#RRGGBB` 会被清空）→ **新增 `color` 布局类型**（校验 `_HEX` 正则）。

### 3.2 新增 layout 字段（LAYOUT_SPEC，共 25 个）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `font_family` | str(任意名) | `""` | 全局字体族名；`""`=维持现有回退链（雅黑→黑体→宋体）。**注意：不用 asset 文件名校验**，需为它开 `str_free` 类型 |
| `title_bold` / `body_bold` / `sub_bold` / `badge_bold` | bool | `False` | 粗体 |
| `*_italic` | bool | `False` | 斜体 |
| `*_underline` | bool | `False` | 下划线 |
| `*_strike` | bool | `False` | 删除线 |
| `*_stroke` | bool | `False` | 描边开关 |
| `*_stroke_color` | **color** | `#000000` | 描边颜色 |

（`*` ∈ {title, body, sub, badge}，共 4×6=24 + font_family = 25）

角色 → 现有颜色字段映射（渲染时按 role 自动取样式）：

| 角色 role | 对应文本 | 对应颜色 |
|---|---|---|
| `title` | 卡片标题 | `t.title` |
| `body` | 正文/列表文字 | `t.text`（body 色） |
| `sub` | 次要说明文字 | `t.text_sub` |
| `badge` | 徽章/角标文字 | `t.badge_text` |

### 3.3 校验规则（themes_store.validate_layout）

```
color 类型:   值必须匹配 ^#[0-9A-Fa-f]{6}([0-9A-Fa-f]{2})?$，否则回落默认
str_free 类型: 原样保留字符串（长度 ≤64），仅防注入字符（\0 与换行剥除）
bool 类型:    现有逻辑不变
```

### 3.4 向后兼容

- 存量主题 JSON 无这些字段 → validate_layout 缺省填默认 → 渲染结果与现在**逐像素一致**（默认关样式、字体走原回退链）。
- 预设按钮（neon/light）不含样式字段 → 套用预设不清空用户样式（`defaultsLayout()` 只填缺省，套预设走 `Object.assign` 不动 layout——现状如此，维持）。

## 4. 后端渲染设计

### 4.1 fonts.py 扩展（不重写，在现有回退链之上加「字体族」层）

```
scan_families() -> list[FamilyInfo]
  扫描 _CUSTOM_DIR（data/fonts，用户自放，优先）+ _SYSTEM_DIR（C:\Windows\Fonts）
  扩展名 .ttf/.otf/.ttc；对每个文件 ImageFont.truetype(path).getname() 取 (family, style)
  style 名含 bold/bold*  → 记 bold 变体；含 italic/oblique → 记 italic 变体；其余 regular
  模块级缓存 _FAMILY_CACHE（进程内一次）；每族记录 cjk: bool（getmask("喵") 非空判定）
  容错：单文件解析失败跳过并记一次 WARNING（坏字体不能拖垮扫描）

load_family(family: str, size: int, bold=False, italic=False) -> FreeTypeFont
  1) family=""            → 走现有 fonts.load("bold" if bold else "regular", size)（原回退链）
  2) 族内匹配变体文件:
       bold+italic → italic 文件优先，缺则 bold 文件（斜体由画布仿射补）
       bold        → bold 文件，缺则 regular 文件（伪粗由画布补）
       italic      → italic 文件，缺则 regular 文件（斜体由画布仿射补）
  3) family 不在扫描结果 → WARNING 一次 + 回退第 1) 步（绝不抛异常，CLOSE-02）
  缓存 key: (family, bold, italic, size)
```

### 4.2 canvas.text 接入（唯一改动收口）

```
Canvas.__init__(..., theme=None)  新增可选参数；新增 Canvas.for_theme(t, w, h) 便捷构造
text(pos, text, size, color, role, anchor, *, style=None):
  style 为 None 时自动从 self.theme 按 role 解析（TextStyle dataclass:
  bold/italic/underline/strike/stroke/stroke_color），templates 零调用点改动
```

渲染管线（在现有 `draw.text` 之上分层叠加）：

```
1. 选字体:   fonts.load_family(theme.font_family, size, bold, italic)
2. 伪粗:     有 bold 变体文件 → 直接用；否则 stroke_width=1, stroke_fill=同色
3. 描边:     style.stroke → stroke_width=max(1, size//12), stroke_fill=style.stroke_color
             （与伪粗叠加时取 max，stroke_fill 取描边色——描边优先级高于伪粗）
4. 绘制:     draw.text(xy, text, fill, font, anchor, stroke_width, stroke_fill)
5. 划线:     w = draw.textlength(text, font)
             textbbox(anchor=anchor) 拿文字矩形 →
             下划线 y = bbox.bottom + size*0.08；删除线 y = (bbox.top+bbox.bottom)/2
             draw.line((x0, y, x0+w, y), fill=fill, width=max(1, size//14))
             注意 textlength 不含 kerning 修正误差（≤1px 可接受，文档明示）
6. 斜体:     有 italic 变体 → 已在第 1 步；否则:
             临时 RGBA 图（textbbox 尺寸 + 余量）→ draw.text →
             img.transform(size, AFFINE, (1, -0.2, 0.2*h, 0, 1, 0), BILINEAR) →
             按 anchor 偏移 alpha_composite 回画布（仅 italic 时走此慢路径）
```

### 4.3 API

```
GET /api/pic/themes/fonts
  → { ok, fonts: [ {family, cjk, has_bold, has_italic} ... ] }
  cjk 字体排前（QQ 卡片中文场景），其余按名称排序；前端下拉搜索
```

editor.py `_themes_list` 无需变更（layout_spec 动态下发新字段，前端自动渲染开关/滑块）。

## 5. 前端 UI 设计（editor_page.html）

### 5.1 控件布局

新增控件组「**文字样式**」（位于「排版」组之后），每角色一行：

```
标题文字   [B] [I] [U] [S̶]  [描边⬤] [#000000 ▾]
正文文字   [B] [I] [U] [S̶]  [描边⬤] [#000000 ▾]
次要文字   [B] [I] [U] [S̶]  [描边⬤] [#000000 ▾]
徽章文字   [B] [I] [U] [S̶]  [描边⬤] [#000000 ▾]
```

- `[B][I][U][S̶]`：四态开关按钮（同现有 `.mini` 开关风格），激活态高亮（Word 按钮形态）
- `[描边⬤]`：开关 + 紧跟描边色块（色块点击弹 Coloris，关闭时置灰）
- 字体选择放「排版」组：`字体 [下拉搜索 ▾]`，首项「默认（跟随系统回退链）」

### 5.2 实现要点

- 开关行复用 `layoutRow` 的 bool 渲染（layoutSpec 自动出现），但一行 6 个字段太散 → 新建 `styleRow(role)` 定制紧凑渲染（读 S.layout[`${role}_bold`] 等 6 个字段）
- 描边颜色是 **layout 的 color 字段**，不走 `setColor`（那是 colors 表）→ 新增 `setLayoutColor(key, hex)`；Coloris onChange 按 `input.dataset.layoutKey` 分流（与 `dataset.key` 区分，避免写错到颜色表）
- 字体下拉是动态列表（来自 `/api/pic/themes/fonts`）→ layoutRow 新增 `font` 类型渲染（`<select>` + 搜索 input 过滤），选中写 `S.layout.font_family`
- 所有改动走 `setLayout()`/`setLayoutColor()` → pushHistory（可撤销）→ schedulePreview（260ms 防抖实时预览）

## 6. 兼容与降级

| 场景 | 行为 |
|---|---|
| 老主题无样式字段 | 全部默认关闭，渲染逐像素与现在一致 |
| 字体族不存在（用户改名/字体被卸载） | WARNING 一次 + 回退原回退链，**不抛异常不崩渲染** |
| 无粗体变体 | stroke_width=1 伪粗 |
| 无斜体变体 | 仿射剪切伪斜 |
| 极小字号（<12px）+ 描边 | 描边宽度限幅 max(1, size//12)，避免笔画糊死 |
| data/fonts 用户字体损坏 | 扫描跳过该文件，不影响其它字体 |

## 7. 测试计划（机器判定：assert + 非零退出）

### 7.1 pytest（`qq_bridge/tests/test_text_style.py`）

1. `validate_layout` 新字段缺省/越界/非法色值回落
2. color 类型：合法 `#RRGGBB` 保留、非法 `javascript:` 清为默认（防注入）
3. `scan_families`：返回非空、含 cjk 标记、结构完整（幂等：二次调用走缓存）
4. `load_family("")` 回退原链与 `fonts.load` 等价；不存在的族 → 回退不抛异常
5. `load_family(family, bold=True)`：有 bold 变体的族返回 bold 文件实例
6. 渲染像素差异断言：
   - title_bold=True vs False → 同文本渲染 **bytes 不同**
   - title_stroke=True（白字黑边）→ 文字边缘出现描边色像素（采样文字 bbox 边缘带）
   - title_underline=True → 文字下方出现与 title 色一致的横向像素带
   - title_strike=True → 文字中部出现横向像素带
   - title_italic=True → 渲染图与 upright 图不同（无 Italic 变体时走仿射路径）
7. 默认主题（无样式）渲染与改造前基线**逐像素一致**（回归保护）

## 8. 验收步骤（用户真实界面）

1. 打开 `http://127.0.0.1:8080/pic/theme-editor`
2. 右侧找到「文字样式」组 → 点标题行的 **B** → 预览里标题立刻变粗（伪粗或真粗）
3. 开「描边」→ 点旁边色块选白色（深底卡片）→ 标题出现描边
4. 「排版」组换字体（选一个中文族）→ 全卡文字换字体
5. Ctrl+Z 逐级撤销；保存主题 → 刷新页面重新加载 → 样式仍在

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 仿射斜体慢路径拖慢预览 | 仅 italic 且无变体时走；临时图尺寸=textbbox+余量（很小）；260ms 防抖内可完成 |
| 字体扫描首次 ~1-2s | 进程内缓存 + API 首次调用时惰性扫描；bridge 启动不受影响 |
| textlength kerning 误差 | ≤1px，划线长度视觉可接受（文档明示不再逐字修正） |
| 字段多（25 个）UI 拥挤 | 紧凑一行 6 控件 + 组折叠；不用 25 行散开 |
