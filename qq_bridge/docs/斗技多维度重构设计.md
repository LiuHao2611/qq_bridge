## 0. 一句话

把斗技从「一行 brief + 一个伤害数字」升级为「主定位 + 多维度效果原子 + 门控代价」，
并让这些效果**真正进入战斗计算**，使低数值技能靠战术价值立足，而不是无脑比谁数字大。

---

## 1. 问题诊断（源码核实，非猜测）

### 1.1 表层：展示简陋

截图里的「本宗斗技」名录卡，每行只有：`brief 一句话` + `品阶/类型/斗气%`。
四槽专用卡 `doupo_skills` 虽然有一条 desc，但 `build_skills_data` 第 256 行用的是
`e.get('brief') or e.get('desc')`——**优先取 brief**，所以完整 desc 也被压成一句话，
右侧伤害面板只有「基础倍率/当前倍率/期望单击」三个纯伤害数字。

### 1.2 根因：多维效果全是「死文本」

`skill_book.py` 的每条 `desc` 其实已写满多维度效果（见 §4），例如：

| 斗技 | desc 里真实存在的效果 | 现在卡片呈现 |
|---|---|---|
| 九幽冥手 | 200% 伤害 + **无视 30% 防御** + 穿空间 | 「漆黑大手穿空，无视30%防御」一句话 |
| 天冥血掌 | 200% 群体 + **减疗 50%×2** + **自损 8% 体力上限** | 一句话 |
| 燕返击 | **反弹 40%**（可成长）+ 怕毒/火/灵魂 | 一句话 |
| 铁山拳 | 108% + **10% 眩晕** | 一句话 |

这些效果既**没结构化**（全塞在 `desc` 字符串里，`kind`/`scope` 是单值枚举装不下），
也**不进战斗**（`core._hit()` 只按 `dmg` 倍率算一次伤害）。
结果：四槽里 N 门技能实际只有 N 个伤害数字在比大小 → 玩家当然无脑选高倍率。

### 1.3 数据核实

截图 23 名 = `catalog("tianmingzong")` 23 条（本宗 11 + 通用 12），一一对应，
差异全是 OCR 误读：铁山靠→铁山拳、蹭步→爆步、御力水镜→卸力水镜、
大灵龙拳→大冥龙拳、天冥操罗手→天冥修罗手、噬血化骨手→嗜血化骨手、水爆蛇罗→水曼陀罗。
原著语料对 11 门本宗斗技逐章命中 10 门（`tmp/tianming_novel_search/`）。

## 2. 调研结论（两路子代理）

### 2.1 外部范式（纯文本 / Roguelike / MUD）

- **组合优于继承**：成熟系统把技能拆成「主定位 + 效果原子数组 + 标签」
  （CDDA `tec_*`、杀戮尖塔 keyword、Unreal GAS GameplayTag）。
  10 来种效果原子即可拼装出 20+ 差异化技能。
- **反无脑红线**：每个有意义的行为，须在【输出】【资源】【时机】至少一项有显著定位；
  高威力必配 gate（高消耗/长冷却/特殊条件/自损）。属性克制、连招协同、控制链、
  维度转化、风险回报、状态免疫，都能让低数值技能有不可替代位。
- **三层呈现**：卡片正面（主数值 + ≤3 副维标签）→ 详情（每维精确数值/条件/克制）
  → 战斗日志（逐维播报），让玩家「感知到多维度」而非一个总数。

### 2.2 内部数据盘点

- 现有 `desc` 已是现成效果矿，无需凭空编；只需结构化。
- `kind`/`scope` 单值枚举不足以表达复合效果 → 必须新增 `role` + `effects` 字段。

## 3. 数据结构设计（effect list）

### 3.1 新增字段（写入 `skill_book._s`）

```
role     : 主定位标签  输出/续航/控场/异常/爆发/防御/位移/功能
effects  : 效果原子数组 [{t, v, d, p, ...}]，见 3.2
gate     : 限制/代价文本（部分已有，从 desc 抽出）
```

### 3.2 效果原子词表（战斗可消费）

| t | 语义 | 参数 | 战斗效果 |
|---|---|---|---|
| `dot` | 持续伤害（毒/流血/灼烧） | v=每回合比例, d=回合, kind | 命中后挂目标，目标行动前扣血 |
| `lifesteal` | 吸血 | v=比例 | 命中回血 |
| `pierce` | 破防/无视防御 | v=比例, p?=概率 | 命中时降低目标有效防御 |
| `debuff_atk` | 降攻 | v, d | 目标攻击下降 |
| `debuff_heal` | 减疗 | v, d | 目标回血下降（PVP/药效） |
| `stun` | 眩晕 | p=概率, d | 目标跳过下次行动 |
| `silence` | 禁技 | d | 目标下次不能用技能 |
| `root` | 定身/拉近 | d | 打断目标行动 |
| `reflect` | 反伤 | v=比例 | 受击反弹 |
| `reduce` | 减伤 | v, d, vs_heavy? | 自身受伤下降 |
| `evade` | 闪避 | v, d | 自身闪避上升 |
| `chain` | 连击加成 | n=连击数, v | 连续命中后加伤 |
| `cond` | 条件加伤 | cond=fear/defensive/fire, v | 满足条件时加伤 |

### 3.3 消费闭环（不破坏平衡的关键）

- **主伤害公式 `damage_schedule` 完全不动** → 怪物血量反解口径不变、`test_monster_scaled_tracks_player` 斩杀窗口不变。
- 效果在 `fight`/`duel` 里**真实生效**，但主要是「续航/防御/控制/条件」价值，
  让低伤技能有立足点；增益/破防类幅度受效果数值本身约束（30% 破防、15% 降攻…），温和。
- 战斗日志逐条播报效果（「血毒每回合 5%」「反弹 40%」「破防 30%」），玩家能看到多维度。

## 5. 卡片呈现规范（card-design 度量优先）

### 5.1 四槽专用卡 `doupo_skills`（重点改造）

每门斗技一块，信息层级：

```
[阶] 斗技名                    Lv.3/5
完整 desc（施展→效果→限制，全文，17px 自动折行）
效果维度条：伤害【高 160%】 · 破防 30% · 续航 25%   ← 从 effects 渲染，标签化
五段斗气条（保留）
伤害面板（保留：基础/当前/期望单击）
下级预估 + 门控提示
```

- 主数值用大字，`effects` 用「标签 chip」平铺，**显式 gap**、度量排版，禁止空格凑间距。
- 效果中文名映射：`dot→毒/流血/灼烧`、`pierce→破防`、`lifesteal→吸血`、`stun→眩晕`…
- 完整 desc 必须展示（不再优先 brief）。

### 5.2 名录卡 `doupo_list`（本宗全部）

每行副行改为：`主定位 · 阶位 · 类型 · 斗气% ｜ 维度标签（≤3）`，
`note` 行放一句完整 desc 摘要。仍走 `check_boxes` 自检。

## 6. 反无脑红线（写入规则 + 门禁）

1. 每门斗技必须至少在【输出】【资源】【时机】之一有显著定位；禁止纯更高数值的中性技能。
2. 黄阶→天阶的差异应体现在**维度数量与特殊条件**，不是单一伤害数字线性放大。
3. 每门至少 1 个效果原子参与战斗/搭配；低伤技能（dmg<1.2）必须带 ≥1 战术维度。
4. 高威力招必配 gate（高耗/长 CD/特殊条件/自损）。

门禁 `tools/check_skill_multidim.py`：校验 23 门 role/effects 完整、低伤必带战术维度、
effects 类型全在词表内、desc 与 effects 数值一致。违规 exit 1。

## 7. 实施顺序

1. `skill_effects.py`：效果词表 + 中文标签 + 战斗消费函数（纯函数，可单测）。
2. `skill_book.py`：`_s` 增 role/effects/gate；天冥宗 23 门填全（先满足用户「先做本宗」）。
3. `skills.py::_to_entry`：透传 role/effects/gate。
4. `core.py::_hit/fight/duel`：消费效果 + 战报播报；damage_schedule 不动。
5. `card.py`：build_skills_data/build_roster_data 展示完整 desc + 维度标签。
6. `pic/templates/doupo_skills.py`：维度条度量排版（card-design）。
7. 测试：单测战斗效果 + 卡片 check_boxes + 门禁；回归全量。
8. rebuild + 三层 md5 + 容器出图 + commit + push。
