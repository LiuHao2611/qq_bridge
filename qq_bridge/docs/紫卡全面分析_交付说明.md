## 2. 数据纪律（绝不编数）

- **主路径 = 紫卡截图 OCR**：`riven_img_parse` → 真实词条/等级/倾向 → `riven_card.build_card_data`（区间与均值）、`_sim`（击杀效率）、`_scores`（评分）。
- **武器名路径**：只填真实可查数据（WFM 挂牌中位价、本地配卡库 MOD、武器名）；依赖截图的词条行/融合行/评分/击杀效率**如实标「需紫卡截图」「—」**。
- **市价（2026-11-10 修订）**：WFM 挂牌要价·非成交价（中位，白金）。左盒「市场价格预计」按**真实匹配样本分层**：L1 `exact.status=="ok"`（正负面相同、同等级精确匹配中位价）→ L2 `n>=3`（`match_tier` 层级低价视图中位价，并显式标「匹配层级：…｜样本 N 条」）→ L3 才诚实写「暂无匹配样本」。「零洗中位价」只取 rank0 未洗挂牌 `market["zero"]`，**绝不拿 rank8 的 `med` 冒充**；市场失败态把原因写进卡面，不残留旧价格。唯一实现为 `game_tools/riven_price.py`，`riven_full._price_boxes` 只做委托。
- **词条价差预估（2026-11-10 修订）**：WFM 无 fuse 字段、无词条成交价全量分页 → 右盒是**独立模型估值**（同等级中位 `med` + 推荐负词条同分位溢价 `rec_neg.delta`），脚注恒为「模型预估 谨慎参考」；sub 逐字为「来源：wm市场|置信度N%」，置信度按 `min(99, n/20*100)` 由样本数推导，**不自造「样本 n=」字段、不写死 80%**；只有市场获取失败才写「暂无实盘样本 / 来源：wm市场|窗口样本不足」。**不把模型估值冒充实盘成交价**。
- **最近观测（2026-11-10 修订）**：按参考卡写相对时间「最近观测：X小时内 / X天内」，由真实 `market["ts"]` 换算，不再直接印绝对时间戳；无时间戳写「最近观测：暂无」，不伪造。
- `reference_sample()`（`#紫卡全面 样例`）是**版式复刻夹具**：`sample=True`，卡脚注与数据源均明确标「版式样例·非实时数据」，仅用于像素对齐回归与显式预览，绝不冒充真实查询。

### 2026-11-10 追加验证：无匹配样本全量对齐（用户 `895747a6…png` + 局部截图）

- **为什么改**：对 `data/qq_files/` 里 7 张 655×1920 历史紫卡价格区逐张裁剪，`n=27`、`n=41` 等有样本卡仍一律显示「暂无匹配样本」，确认是代码写死而不是真实状态。用户 2026-11-06 08:59 提供的 Warframe Rabbit 原卡（md5 前缀 `f6f65e5b`）逐字为：左盒「市场价格预计 / 暂无匹配样本 / 零洗中位价：369P / 暂无匹配样本」、右盒「词条价差预估 / 386P / 来源：wm市场|置信度80% / 模型预估 谨慎参考」、底部「最近观测：13小时内」——「无匹配样本」只指**精确匹配样本不足**，其余信息照给。外部 RivenRadar 的 comparable-bucket（同武器＋正词条组合＋负词条类别分桶、15 分位锚＋25~75 区间＋confidence）也在样本不足时降级到更宽桶并降置信度，而不是一律报无。
- **外部基准**：`tests/fixtures/rabbit_riven_price_reference.json` 把上述价格区抄成 JSON，门禁只读取不改表，避免「照着当前实现反改标准」。
- **验收**：`check_riven_price_boxes.py --check` 逐字基准 0 偏差 + 6 种真实 market 快照（L1 精确 / L2 同负词条 / L2 无零洗样本 / L2 溢价 0 / L3 样本不足 / L3 未获取）问题 0；渲染 `_shot_riven_price_matched.png`（big=`380P`）与 `_shot_riven_price_no_match.png`（big=中文）均 655×1920、`check_boxes` 溢出 0 / 重叠 0 / 间距 0；`--selftest` 9 类注入反例全部被拦；`test_riven_full.py` ALL PASS（像素最大偏差仍 6px、四条结构线 0px 差）；`check_riven_full_layout.py` 8 样本（新增 exact/no-match 两态）全 0 问题。

## 4. 没验证到的 / 已知限制

- **全量 `pytest` 回归未能跑**：本 worktree 缺部署期才有的 `qq_bridge.connector` / `qq_bridge.session` 等模块，`qq_bridge/tests/test_pic_*.py` 等存量用例在**收集阶段**即失败（与本次改动无关，任何改动前都一样）。已在隔离夹具 + 真实 `pic/__init__.py` 加载两个层面补了可跑的验证；真机 E2E 需在部署环境发 `#紫卡全面 样例` 与截图确认。
- **字形差异**：参考卡字体与本机微软雅黑不同，字号按墨迹宽度反推后位置对齐（≤6px），但单个字形轮廓不可能逐像素相同。
- **背景**：按用户要求「除了背景」，未复刻粉色兔纹底图；MOD 缩略卡 / Q 版插画作为前景内容保留。
- **配卡 MOD 图**：参考卡 8 张缩略图取自用户参考卡；真实武器名路径若本地配卡库无图，模板画深色占位卡框 + 真实 MOD 名，不编造图片。
- **2026-11-10 口径边界**：Rabbit / RivenRadar 的估价疑似依赖自有历史价格库与相似度匹配，本项目**不与之同源**，因此只能按 WFM 真实挂牌做同语义的层级降级与模型估值，不能、也不会复刻别人卡上的绝对值（369P / 386P）；外部基准只用于校验**字段结构、逐字格式与降级语义**。真实 QQ 客户端线上 `#紫卡全面` + 实时 WFM 端到端出图仍需用户确认，本轮证据是离线状态机、宿主渲染截图与容器内同链路渲染。
