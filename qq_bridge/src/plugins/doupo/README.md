# 斗破苍穹·双帝之战（QQ 群聊文字版 · NoneBot2 插件）

把 J2ME 原版《斗破苍穹2-双帝之战》搬进 QQ 群，做成纯口令文字游戏。
架构与「修仙」插件一致：`config`(数据) → `core`(纯函数) → `store`(json) → `commands`(业务) → `__init__`(matcher)。

## 数值来源：`[源码]` 与 `[调参]`

`config.py` 里每个数值都标了来源，**改数值前先看注释**：

- **`[源码]`** = 反编译 J2ME 原版（`src/*.java`）+ 真机截图取证，逐位 1:1 搬过来，不要动：
  - 属性：`c_stat(base,lv) = base*10 + 阶²*base*10 + base*lv`，`阶=(lv-1)/9`（`ah.java:165`）
  - 强化：`base×(1+0.1·L(L+1)/2)`；消耗炎星石 = `L+1`；`L=9` 硬编码 2000/2000/1000/1200（`h.java:80-102`、`l.java:361`）
  - 暴击% `= 10+(敏捷+30)/100`、闪避% `= 5+(敏捷+20)/200`（`y.java:155-157`）
  - 境界名、斗技名与快捷键、异火说明、丹方名单、药材描述 —— 全部实机原文
- **`[调参]`** = 原版是单机节奏，群里照搬会玩不动，只调**速度**不动**形状**：
  - `exp_need(lv) = 400·lv²`（原版单级 205000，群里几周升不了一级）
  - 异火喂养 `5000 → 60` 药渣（药渣只来自炼药失败 +3，5000 要 1600 次失败炼药）
  - 怪物数值整体改为**按玩家属性动态缩放**，理由见下

真机校验项已写进 `test_core.py::test_panel_matches_real_screen`：
力量 575 / 敏捷 480 / 斗气 315 / 防御 342 / 体力 880 / 机缘 1，与实机人物面板逐格一致。

## 怪物为什么是「动态缩放」而不是写死数值

这是本插件调试过程中踩的最大的坑，改动前请先读 `core.monster_scaled` 的注释：

1. 玩家属性每 9 级有一次 `阶²` 的**平方级跃升**，写死血量的怪在跃升前后会从「白给」直接变「必死」——
   实测固定数值表下 16~18 级胜率 0%。
2. 血量不能按「单回合平均伤害 × 回合数」外推：蓝只够放 5 次斗技（cost = mp_max//5），
   第 6 回合起只能普攻，输出掉到 42%。曾因此出现 22 级要 11 回合才杀得死。
3. 物种倍率（血 ×1.05 攻 ×1.00）叠加等级差（±14%）会把难度比值推出刀尖，整段胜率翻转。
   现在物种难度直接写成 `hard = 怪斩杀回合 ÷ 玩家斩杀回合`，单调可调。
4. 胜负本质是「怪能否在玩家击杀前一回合打死人」的整数比较，**没有伤害浮动时胜率只会在 0/50/100 之间跳**。
   `MON_DMG_VAR=0.25` + `MON_ROUND_RATIO=1.10` 是扫出来的组合。

调参只动 `MON_ROUND_RATIO`（全局难度），不要动各物种 `hard` 的相对差。

## 机器验收

```bash
python src/plugins/doupo/test_core.py        # 纯函数层：31 项
python src/plugins/doupo/test_commands.py    # 口令业务层：78 项
python src/plugins/doupo/test_e2e.py         # 真实 matcher + 真实事件：47 项
python src/plugins/doupo/_balance.py         # 数值平衡模拟（调参工具，非单测）
```

三个测试都是自带 runner，exit 0 = 全绿。

`_balance.py` 的判定口径（写在它自己的 docstring 里）：
胜率下限 70%（不能有打不过的死局）、上限 99.5%（不能白给，1 级豁免）、
平均回合 2~10、升到斗帝总场次 120~400。
当前实测：胜率 73%~99.5%，回合 4.7~5.2，残血 21%~44%，总场次约 169 场。

`test_e2e.py` 会**同时加载 xiuxian 与 doupo**，验证两条：
- 修仙的 `突破 / 背包 / 排行榜 / 商店 / 任务 / 炼丹` 不会触发斗破
- 闲聊与「我想看斗破苍穹动漫」不会误伤

## 文件

| 文件 | 职责 |
|---|---|
| `config.py` | 全部数值表，`[源码]` / `[调参]` 分类标注 |
| `core.py` | 纯函数（属性/战斗/强化/炼药/斗技/异火/任务/商店），零 nonebot |
| `store.py` | json 落盘 + asyncio.Lock 原子写 |
| `commands.py` | 业务层，`MENU_GROUPS` 是菜单唯一源 |
| `__init__.py` | 25 个 matcher，全部 `priority=5 + block=True` |
| `test_core.py` / `test_commands.py` / `test_e2e.py` | 三层测试 |
| `_balance.py` | 平衡模拟（调参用） |
| `data/doupo.json` | 存档（可用 `DOUPO_DATA_PATH` 改到别处） |

⚠️ 口令正则的前缀必须写成 `_pat(kw)`：nonebot 的 `RegexRule` 匹配对象是 **CQ 码字符串**
（`[CQ:at,qq=10002]dp抢`），不是纯文本。`^` 之后不吃掉前置 CQ 码，所有「@某人 + 口令」的玩法都会失效。
