# 斗破苍穹·双帝之战（QQ 群聊文字版 · NoneBot2 插件）

把 J2ME 原版《斗破苍穹2-双帝之战》搬进 QQ 群，做成纯口令文字游戏。
架构与「修仙」插件一致：`config`(数据) → `core`(纯函数) → `store`(json) → `commands`(业务) → `__init__`(matcher)。

## 口令清单（共 25 条 · 纯中文）

斗破与修仙**共用同一套纯中文口令**（`突破` 就是 `突破`），不再有 `dp` 前缀。
隔离靠 `src/game_mode.py` 按 **QQ 号**记住每个人当前在玩哪个游戏：

- 发 `斗破菜单` → 这个人后续所有口令都走斗破；发 `修仙菜单` → 都走修仙。
- **菜单是唯一切换口**。入口口令（`斗破菜单` / `入道` / `我要修仙`）也会设定模式。
- 没选过模式就打口令 → `game_router` 提示先发菜单；在斗破模式打修仙专属口令 → 提示切换。
- 口令前仍可带 `@机器人` / `#` / 空格，由 `_pat()` 吃掉。

## 数值来源：`[源码]` 与 `[调参]`

`config.py` 里每个数值都标了来源，**改数值前先看注释**：

- **`[源码]`** = 反编译 J2ME 原版（`src/*.java`）+ 真机截图取证，逐位 1:1 搬过来，不要动：
  - 属性：`c_stat(base,lv) = base*10 + 阶²*base*10 + base*lv`，`阶=(lv-1)/9`（`ah.java:165`）
  - 强化：`base×(1+0.1·L(L+1)/2)`；消耗炎星石 = `L+1`；`L=9` 硬编码 2000/2000/1000/1200（`h.java:80-102`、`l.java:361`）
  - 暴击% `= 10+(敏捷+30)/100`、闪避% `= 5+(敏捷+20)/200`（`y.java:155-157`）
  - 境界名、斗技名与快捷键、异火说明、丹方名单、药材描述 —— 全部实机原文
- **`[调参]`** = 原版是单机节奏，群里照搬会玩不动，只调**速度**不动**形状**：
  - `exp_need(lv) = 400·lv²`（原版单级 205000，群里几周升不了一级）
  - 异火喂养 `5000 → 60` 药渣（药渣只来自炼药失败 +3，5000 要 1600 次失败炼药）
  - 怪物数值整体改为**按玩家属性动态缩放**，理由见下

真机校验项已写进 `test_core.py::test_panel_matches_real_screen`：
力量 575 / 敏捷 480 / 斗气 315 / 防御 342 / 体力 880 / 机缘 1，与实机人物面板逐格一致。

## 怪物为什么是「动态缩放」而不是写死数值

这是本插件调试过程中踩的最大的坑，改动前请先读 `core.monster_scaled` 的注释：

1. 玩家属性每 9 级有一次 `阶²` 的**平方级跃升**，写死血量的怪在跃升前后会从「白给」直接变「必死」——
   实测固定数值表下 16~18 级胜率 0%。
2. 血量不能按「单回合平均伤害 × 回合数」外推：蓝只够放 5 次斗技（cost = mp_max//5），
   第 6 回合起只能普攻，输出掉到 42%。曾因此出现 22 级要 11 回合才杀得死。
3. 物种倍率（血 ×1.05 攻 ×1.00）叠加等级差（±14%）会把难度比值推出刀尖，整段胜率翻转。
   现在物种难度直接写成 `hard = 怪斩杀回合 ÷ 玩家斩杀回合`，单调可调。
4. 胜负本质是「怪能否在玩家击杀前一回合打死人」的整数比较，**没有伤害浮动时胜率只会在 0/50/100 之间跳**。
   `MON_DMG_VAR=0.25` + `MON_ROUND_RATIO=1.10` 是扫出来的组合。

调参只动 `MON_ROUND_RATIO`（全局难度），不要动各物种 `hard` 的相对差。

九个测试都自带 runner、自己把仓库根加进 `sys.path`（不依赖外部 `PYTHONPATH`），`exit 0 = 全绿`。
`_balance.py` 是数值平衡模拟（调参工具，非单测）：`python src/plugins/doupo/_balance.py`。

`_balance.py` 的判定口径（写在它自己的 docstring 里）：
胜率下限 70%（不能有打不过的死局）、上限 99.5%（不能白给，1 级豁免）、
平均回合 2~10、升到斗帝总场次 120~400。
当前实测：胜率 73%~99.5%，回合 4.7~5.2，残血 21%~44%，总场次约 169 场。

`doupo/test_e2e.py` 会**同时加载 xiuxian / doupo / game_router**，验证：
- 纯中文口令按当前模式分流、菜单是唯一切换口、切换后旧游戏的口令不再命中
- 没选模式 / 打错游戏有友好提示
- 修仙口令不触发斗破、闲聊与「斗破苍穹」这类日常用语不误伤
- `fire(expect_image=True)` 必须真的出图（自举用例防止断言假通过）
- **出图口令必须出图**（用户 2026-11-07 21:17 明确要求并说「记住了」）：建号后连续发
  「人物/斗技/宝库/背包/排行/异火」，全部落在曾有的 25s 冷却窗口内，每条都必须真的带
  `image` 段；禁止降级纯文字、禁止限流、禁止静默。`_throttle.py` 已停用，不得重新接入。
- **人物卡内嵌静态头像**（用户 2026-11-07 22:35「不用放动态人物小人了，截图一个头像就行，放在卡片里」）：
  连续 3 次「人物」，每次必须**恰好 1 个 image 段**、字节头是 PNG 魔数、绝不夹带 GIF，
  且卡片 `(28,96)-(124,192)` 头像框里深色像素 >1500（像素级证明头像真的画进卡片）。
  断言前自清 `<root>/src/data/pic_cache`，防止命中旧缓存造成假通过。

### 人物卡头像怎么来的

`avatar.py::HEADSHOT_BOXES` 给四档 idle GIF 各存一个经网格图目视校准的裁剪框，
运行时取**首帧**裁出头部，整数倍 `NEAREST` 放大后居中合成 96×96 透明 PNG，
由 `card.build_data()` 以纯 base64 传给 `pic/templates/doupo.py` 画进卡片左侧圆角框。
`人物/属性/面板` 只发这一张卡片；`入道` 建号时的一次性欢迎动图仍在（`入道` 是既有出图口令）。

⚠️ 不落新的 PNG 素材文件：本仓 `.gitignore` 忽略 `*.png` / `*.gif`，二进制素材进不了 git，
新增静态文件只会变成「本机有、clone 下来没有」的幽灵资源。运行时从 GIF 现裁，代码可完整上传；
GIF 缺失时模板画剑形占位，卡片照常出图。
⚠️ 头像参数必须是**可 json.dumps 的字符串**（base64），不能塞 `PIL.Image`：
`pic` 的磁盘缓存 key 要对全部 params 做 JSON 序列化，带内存地址的对象会让缓存永久失效。

两个 e2e 都把 `DOUPO_DATA_PATH` / `XIUXIAN_DATA_PATH` / `GAME_MODE_PATH` / `QQ_LOG_DIR`
改道到临时目录，不会污染线上存档与日志。

## 文件

| 文件 | 职责 |
|---|---|
| `config.py` | 全部数值表，`[源码]` / `[调参]` 分类标注 |
| `core.py` | 纯函数（属性/战斗/强化/炼药/斗技/异火/任务/商店），零 nonebot |
| `store.py` | json 落盘 + asyncio.Lock 原子写 |
| `commands.py` | 业务层，`MENU_GROUPS` 是菜单唯一源 |
| `__init__.py` | 25 个 matcher，全部 `priority=5 + block=True`；除 3 个入口外均带 `rule=_mode_is("doupo")` |
| `test_*.py` | 六套自带 runner 的测试（core / commands / card / avatar / throttle / e2e） |
| `_balance.py` | 平衡模拟（调参用） |
| `data/doupo.json` | 存档（可用 `DOUPO_DATA_PATH` 改到别处） |
| `src/game_mode.py` | 按 QQ 号记录当前游戏模式，落 `data/game_mode.json`（`GAME_MODE_PATH` 可改） |
| `src/plugins/game_router/` | `priority=6` 兜底：无模式 / 错模式给友好提示，不误伤闲聊 |

⚠️ 口令正则的前缀必须写成 `_pat(kw)`：nonebot 的 `RegexRule` 匹配对象是 **CQ 码字符串**
（`[CQ:at,qq=10002]抢`），不是纯文本。`^` 之后不吃掉前置 CQ 码，所有「@某人 + 口令」的玩法都会失效。

⚠️ 新增口令必须同时登记到 `register_keywords("doupo", [...])`，否则没选模式 / 打错模式时
`game_router` 认不出这是口令，给不出提示。菜单（`MENU_GROUPS`）也要同步加一行，
`test_commands.py` 会断言菜单条数等于 matcher 数。
