# 文字修仙 · QQ 群聊多人小游戏

纯口令、零 LLM 的群聊文字修仙。目标：**让人上瘾，但不是上班**——
被动成长 + 社交摩擦驱动每日活跃，随机事件炸群制造好奇，绝不强制打卡。

---

## 一、设计原则（来自社区调研，集百家之长）

| 机制 | 作用 | 对应诉求 |
|------|------|----------|
| 闭关（被动成长） | 只有**发「闭关」之后**才按分钟产出修为（不闭关一点不涨） | 不强制每日任务，但也不让人挂机自涨 |
| 悬赏（用时间换灵石） | 接一个 1~3 小时的任务，到点结算；一次只能接一个 | 每天有理由回来一次，不逼你刷 |
| 抢/偷/切磋（对抗） | 社交摩擦 = 每日群消息的真正引擎 | 每天都有人在群里发消息 |
| 世界Boss / 秘境 / 奇遇（随机） | 后台不定时炸群，制造好奇 | 非考核、非上班感 |
| 领取机缘（可选） | 随机惊喜、不卡进度、连领加成 | 想去就去，不逼每天 |
| 排行榜 / 宗门战 | 竞争与归属 | 长期留存 |
| 寿元只因主动突破增减 | 不登录**不**被惩罚 | 杜绝打卡焦虑 |

> 关键取舍：玩家**离线/挂机不会掉境界、不会死**。寿元只在你**主动突破**时
> 增减（成功加寿、失败小幅折寿）。这样"几天没空上号"也不会掉队，避免上班感。

## 一·五、数值出处（2026-10-26 起：成长与突破不自行设计）

初版数值是自己拍的（修为需求 ×2.5、产出 ×2），净效果**越升越快** —— 单灵根纯挂机
1.93 小时从凡人到真仙，而且突破没有冷却，玩家能连着破。用户实测 12 分钟从筑基冲到
金丹 `3607/2000`，观感是"还修行啥"。所以整体换成**成熟开源项目的表与机制**：

| 项 | 来源（MIT） | 说明 |
|----|------|------|
| 境界 / 修为需求 / 突破率 | [Sam5440/nonebot_plugin_xiuxian](https://github.com/Sam5440/nonebot_plugin_xiuxian) 的 `data/xiuxian/境界.json` + `突破概率.json` | 38 级，需求 100 → 1.61 亿；突破率 40% → 1%。逐行照抄见 `config_open.py` |
| 闭关产出 / 上限 / 破镜 CD / 失败惩罚 | **同仓** `data/xiuxian/config.yaml` | `closing_exp=10` / `upper_limit=1.5` / `level_up_cd=60` / `punishment 1~5%` / `level_up_probability=0.3` |
| 悬赏任务 | **同仓** `data/xiuxian/悬赏令.json` | 16 条（采药 5 / 捉妖 5 / 暗杀 6），rate / time / 报酬逐字照抄 |
| 炼丹丹药（36 种） | **同仓** `data/xiuxian/丹药/炼丹丹药.json` | `exp_up` 9 / `level_up_big` 17 / `atk_buff` 10，buff 与配方逐字照抄 |
| 炼丹炉（3 种） | **同仓** `data/xiuxian/丹药/炼丹炉.json` | 产出加成 +0/+1/+2 枚照抄；**无价格字段**，NPC 售价是我们按品级透明换算的适配（见一·六） |

> `QingMuCat/nonebot_plugin_xiuxian_2` 是同源 fork，`closing_exp=30`、`punishment_limit=10`
> 与源不同。本实现取**源项目**值，保证境界表与机制参数同源，不会两套表混搭。

**突破门槛的语义坑**：源项目 `set_closing_type()` 取的是**下一境界的 `power`**，不是 `exp`
（两者只在「结丹境初期」不同：`power 30000` / `exp 20000`）。照源用 `power`。

### 实际节奏（按源码数值实测，单灵根 ×1.3 = 13 修为/分钟）

| 目标境界 | 累计修为 | 纯闭关耗时 |
|---|---|---|
| 筑基境圆满 | 3 万 | 1.6 天 |
| 结丹境圆满 | 21 万 | 11 天 |
| 元婴境圆满 | 69 万 | 37 天 |
| 化神境圆满 | 184 万 | 98 天 |
| 渡劫境圆满 | 6154 万 | 9 年 |
| 太乙境圆满 | 8.26 亿 | 121 年 |

**这不是 bug，是源项目的原貌**：它自己的悬赏奖励只有 60~3000 修为、签到 100~2000/天，
面对 1.6 亿的需求同样够不着 —— 高境界在那边也是传说层。要改快就改
`config.py` 的 `SECLUDE_EXP_PER_MIN`（改 30 即整体快 3 倍，那是 fork 的值）。

## 二、口令清单（群内发送，可选前导 `#`）

| 口令 | 说明 |
|------|------|

| `#修仙帮助` | **玩法细则图片卡**（修为/突破/灵石/悬赏/宗门/Boss 的具体数值，别名：修仙玩法、修仙攻略） |
| `#我要修仙` | 入道，随机灵根，开启仙途 |
| `#我的修仙` | 查看状态卡（顺带结算闭关修为） |
| `#闭关` / `#出关` | 进入/退出闭关；**只有闭关中才涨修为**，每分钟 +10（×灵根） |
| `#突破` | 修为满时冲击下一境界（有概率+折损，成功后调息 60 分钟） |
| `#领取机缘` | 随机灵石，连领有加成（有冷却，非强制） |
| `#秘境` | 随机探索节点：灵石矿/灵药/妖兽/古迹/奇遇 |
| `#悬赏` | 看全部 16 个悬赏任务（成功率/耗时/报酬） |
| `#接悬赏 任务名` | 接下任务，可写简称（如 `接悬赏 玄冰花`）；一次只能接一个 |
| `#交悬赏` | 到点后结算，按任务成功率掷骰，成败都给灵石 |
| `#切磋@某人` | 比拼战力，赢家夺灵石 |
| `#抢灵石@某人` | 抢夺对方部分灵石（输了反损） |
| `#偷灵石@某人` | 偷取（被发现惩罚更小） |
| `#送灵石 100 @某人` | 赠予灵石 |
| `#排行榜` | 本群战力榜前 10 |
| `#创建宗门 名称` | 立派（需先入道） |
| `#加入宗门 名称` | 入派 |
| `#宗门` | 查看本宗门成员与战力 |
| `#宗门战 敌方宗门名` | 两宗门战力对撞（含随机扰动） |
| `#世界boss` | 查询当前本群 Boss 血量 |
| `#讨伐boss` | 出力攻击 Boss，击杀按贡献瓜分奖池 |
| `#商店` / `#坊市` | 看在售商品：炼丹炉（3000/8000/18000 灵石）+ 本源药材（30 灵石/株，按主药类型 2~6） |
| `#买 物品` | 购买：`买 炼丹炉·寒铁铸心炉`、`买 药材2`（发「商店」看全） |
| `#炼丹 丹药名` | 消耗「炼丹炉 + 配方药材」开炉，约 60 分钟成丹（如 `炼丹 洗髓丹`） |
| `#收取丹药` | 炼制到点后领取成品（丹炉越灵，产出越多：+0/+1/+2 枚） |
| `#用丹 丹药名` | 服用丹药：加修为 / 加突破率 / 加攻击（按丹药类型，有境界与每日上限） |

### 前缀兼容（实测覆盖）
- 纯文本：`我要修仙`、`#我要修仙`
- @ 机器人：`@bot 我要修仙`、`@bot #我要修仙`
- @ 对手：`切磋@张三`、`@bot 抢灵石@张三`（会正确跳过 bot 自己，取真正的对手）

> ⚠️ **实现坑（后续改正则务必注意）**：nonebot 的 `RegexRule` 匹配对象是
> `str(event.get_message())`，即 **CQ 码字符串**（`[CQ:at,qq=10002]切磋`），不是纯文本。
> 所以 `_pat()` 的前缀必须是 `r"^(?:\[CQ:[^\]]*\]|\s)*#?\s*"`——循环吃掉
> "CQ 码或空白"的任意交替，否则所有带 `@` 的口令会静默失效（0 回复、无报错）。

> 状态类回复（`我要修仙` / `我的修仙`）与两张说明卡（`修仙菜单` / `修仙帮助`）优先发
> **Pillow 自绘图片卡**（`../qq_bridge/pic` 的 `xiuxian` / `xiuxian_menu` / `xiuxian_help` 模板），
> 渲染任何异常都自动降级为纯文本，绝不因为图挂了而丢消息。
> 卡片文案与 `commands.MENU_GROUPS` / `commands.HELP_GROUPS` **同源**，改口令或改数值只需改一处；
> `test_commands.py` 会拿 `config.py` 的真实数值反查帮助卡文案（改数值忘改文案会直接红）。

### 已知实现不一致（2026-10-26 核对发现，待定改不改）
写帮助卡时逐条对照源码，发现 3 处「字段/文案存在但逻辑没接上」；换开源表时又记 2 条待决项。帮助卡文案一律
按**实现真实行为**写，不写设计意图；这里单列出来，避免下次又被当成"设计如此"：

| 项 | 现状 | 影响 |
|----|------|------|
| 世界Boss 过期 | `spawn_boss()` 写了 `expires = now + 30min`，但**没有任何地方读取** | Boss 不会 30 分钟消失，会一直挂到被打死 |
| 秘境限时 | 后台事件广播「限时30分钟」，`world["secret_open"]` 只写不读，`cmd_explore()` 不校验 | 「秘境」任何时候都能刷，广播的"限时"是空话 |
| 背包道具 | 古迹掉落（残破玉简/古修遗骸/神秘碎片）只进不出，无使用/合成入口 | 纯收藏，帮助卡已如实标注 |
| 丹药 / 炼丹（**已搬 2026-10-26**） | 36 条「炼丹丹药.json」**原样搬**（含 `exp_up` +8000~40000 修为、`level_up_big` +10~30% 突破率、`atk_buff` +720~604840 攻击）；炼丹机制忠实源：`elixir_config` 按**药材主药 type**（2/3/4/6）匹配，故商店按 type 卖「本源药材」、炼丹按 type 消耗。源 `药材.json` / `炼丹炉.json` **无价格字段**（源靠灵田种植 / 世界Boss），**价格是唯一必要适配**（见下「商店与炼丹」小节，透明换算、可随时改）。源 `丹药.json` 的 19 条回血丹因玩家无气血字段**未搬** | 已落地：商店 NPC 只卖炼丹炉 + 本源药材（不发回血丹，否则与悬赏经济脱节）；炼丹需炉 + 药材 + 境界门槛；用丹按类型加修为/突破率/攻击并记每日与累计上限 |
| 进度条渐变方向 | `canvas.gradient_rect(horizontal=True)` 实际是「左=c2、右=c1」（`pic/widgets.py` 坑 1 已记录）。修仙卡已在自己调用处交换实参修正；但共用的 `widgets.progress_bar()` **仍是反的** | 修仙卡已修（左浅右深）；菜单/进度/配额等卡的进度条仍是右端变浅，要不要统一修会改变既有观感，等确认 |

> 前三者都属于**玩法口径**决策（收紧还是放开），不擅自动：收紧会让"秘境"从随时可玩变成

### 一·六、商店与炼丹（2026-10-26 新增，全搬自 Sam5440 开源表）

**数据唯一来源**：[Sam5440/nonebot_plugin_xiuxian](https://github.com/Sam5440/nonebot_plugin_xiuxian)（MIT）的
`data/xiuxian/丹药/炼丹丹药.json`（36 种「真货」）+ `炼丹炉.json`（3 种）。
**不自己写任何数值**，照抄后仅做必要的工程适配。

- **36 种丹药分类**（原样搬，零改动）：
  - `exp_up`（9 种）：洗髓丹 +8000 … 道源丹 +40000 修为（除闭关外唯一主动加修为途径）
  - `level_up_big`（17 种）：筑基丹 +30% … 太乙炼髓丹 +20% 突破率，**每颗只用 1 次**，需对应「圆满」境界（如筑基丹需练气境圆满）
  - `atk_buff`（10 种）：摄魂鬼丸 +720 … 太一仙丸 +604840 永久攻击
- **炼丹机制忠实源**：`elixir_config` 按**药材主药 type**（2/3/4/6）匹配，**不是具体药材名**。
  所以商店按 type 卖「本源药材·2~6 型」，炼丹时按 type 消耗——玩家拿到的就是源项目的配方逻辑。
- **价格是唯一必要适配**（源仓 `药材.json`/`炼丹炉.json` **无价格字段**，源靠灵田种植 + 世界Boss 掉炉）：
  透明换算写于 `config_open.py` 顶部，`SHOP_HERB_PRICE = 30`（灵石/株）、
  `SHOP_FURNACE_PRICE = {4003:3000, 4002:8000, 4001:18000}`（按产出加成反向定价）。
  规则不留魔法数字，随时可改。**没有硬搬源 `丹药.json` 的 `price=100000` 占位值**（那会让 1000 灵石的悬赏失去意义）。
- **炼丹炉产出加成**：陨铁炉 +0 / 雕花紫铜炉 +1 / 寒铁铸心炉 +2 枚（炼成时 `1 + buff`）。
- **用丹效果**：`exp_up`→加修为；`level_up_big`→累加到 `bt_big`，**下次突破时并入成功率、无论成败清零**；
  `atk_buff`→永久加攻击（`power()` 已含 `atk`，零阻力）。三类都有**境界门槛 + 每日上限 `day_num` + 累计上限 `all_num`**。
- **获取途径**：丹药只能「买炉 → 买药材 → 炼丹 → 收丹 → 用丹」整条链产出，NPC 商店**不卖成品丹**
  （源 `goods.json` 只卖 2 种回血丹，玩家无气血字段，照搬无意义）。
- **2026 设计思路取舍**：2026 三家活跃仓库（liyw0205/nonebot_plugin_xiuxian_2_pmv、QingMuCat/nonebot_plugin_xiuxian、
  ganchengcaiyue/nonebot_plugin_simulator_xiuxian）的「坊市」均为**玩家自由定价上架的拍卖制**
  （`auction.py` 证实，开发者不定价）。本项目采用「NPC 固定价卖炉 + 本源药材」的**忠实简化版**，
  保留源的炼丹数值与配方逻辑；若未来要纯拍卖坊市，是另一套更大的经济系统，可再搬。

### 一·七、状态卡字段与「暴击」死字段修复（2026-10-26）

用户反馈「作为一个修仙者，感觉好像少了点什么」——原卡只画了
`名字 / 境界+修为 / 灵根 / 战力·灵石·寿元·战绩 / 宗门·背包 / 提示`，
**战力被压成一个合成值**，且玩家最在意的**突破把握**没上卡。本次补齐：

| 位置 | 新增 | 数据来源 |
|---|---|---|
| 四宫格下方一行 | `攻击 X · 防御 Y · 暴击 Z%` | `p["atk"] / p["def"] / p["crit"]` |
| 境界行右侧 | 修为后缀带突破率（三态） | `core.bt_rate_effective(p)` |

突破率三态（与 `do_breakthrough` 真实公式一致，含失败累积 `bt_bonus` + 丹药 `bt_big`，封顶 100）：
`1200 / 3000 修为 · 突破率 38%`（平时）｜`· 可突破（38%）`（修为够且不在 CD）｜
`· 调息 47 分钟｜成功率 38%`（修为够但 CD 中）｜已至巅峰则**不显示**（`rate_pct=0`）。

> ⚠️ **顺手修掉一个假成长线**：`crit` / `crit_dmg` 从建号起就有值、每次突破 `crit += 1%`（上限 50%），
> 但**全工程从未被读取**——涨到 50% 也毫无作用。若只把「暴击 5%」画上卡，就是一条骗人的数字。
> 现以 `core.crit_mult(p) = 1 + crit × (crit_dmg − 1)` 折成**期望战力加成**接进 `_fight()`
> （切磋/抢劫/偷取/宗门战）与 `boss_hit()`（Boss 伤害数字直接变大），
> 胜负仍是**单次掷骰**，不破坏既有胜率曲线。守护测试：`test_crit_affects_fight`。

## 三、安装 / 加载方式

### 作为 nonebot 插件（推荐）
把 `xiuxian/` 目录放到你的 bot 的插件目录，或在 `.env` 的 `plugin_dirs`
中加入其所在目录，让 `nonebot.load_plugin("xiuxian")` 能找到它即可。
插件在导入时自动注册全部口令 matcher，并随驱动启动后台随机事件循环。

### 本地联调
```bash
cd <repo根>
pip install nonebot2 nonebot-adapter-onebot
python -m xiuxian.bot
```
再用 NapCat 以正向 WebSocket 连到 nonebot 监听端口即可在群里试玩。

## 四、数据落盘（遵守红线）
- 默认落盘：`xiuxian/data/xiuxian.json`（插件内目录）。
- 可经环境变量改到非 C 盘（例如 D 盘）：
  ```bash
  export XIUXIAN_DATA_PATH=/d/your/path/xiuxian.json   # Linux/mac/Git Bash
  # 或 Windows PowerShell:
  $env:XIUXIAN_DATA_PATH = "D:\your\path\xiuxian.json"
  ```
- 持久化用标准库 `json` + `asyncio.Lock` 原子写（临时文件 + `os.replace`），
  单机并发安全，零第三方依赖。

**真的发出一张非空图片**（`fire_img` 断言 base64 体积，防"以为发了图其实是空图"）、
菜单卡与玩法卡**必须是两张不同的图**、修为溢出必须判为「可突破」、
**进度条像素级断言「左浅右深」**（防渐变方向再次反向）、前缀兼容（纯文本 / `#` / `@bot` / `@对手` / 混合）、
私聊拒绝、闲聊不误伤、**matcher 数量必须等于菜单条数**（加了口令忘注册/忘写菜单都会红）、
全部 matcher 为 `priority=5 + block=True`。
它**刻意不加载 `qq_bridge` 主插件**，避免测试触发 LLM 调用；数据落临时目录，不污染线上存档。

`test_core.py` 里的守卫：
- `test_bounty_table_matches_source` —— 悬赏表必须 16 条 / 三类 / rate∈(0,100] / 报酬为正，且**成功率越高报酬越低**（防有人把高成功率任务改成高报酬，变成无脑印钞）。
- `test_bounty_start_finish_and_mutex` —— 一次只能接一个、未到期不可结算、到点按 rate 二选一给钱。
- `test_settle_only_while_secluding` —— **不闭关不产出修为**（就是用户报的那个"突破完又满了"的根因）。
