## 2. 数据纪律（绝不编数）

- **主路径 = 紫卡截图 OCR**：`riven_img_parse` → 真实词条/等级/倾向 → `riven_card.build_card_data`（区间与均值）、`_sim`（击杀效率）、`_scores`（评分）。
- **武器名路径**：只填真实可查数据（WFM 挂牌中位价、本地配卡库 MOD、武器名）；依赖截图的词条行/融合行/评分/击杀效率**如实标「需紫卡截图」「—」**。
- **市价**：WFM 挂牌要价·非成交价（中位，白金）；窗口样本不足如实标「暂无匹配样本」。
- **词条价差预估**：WFM 无 fuse 字段、无词条成交价全量分页 → 恒标「暂无实盘样本 / 模型预估 谨慎参考」，**不编造 386P 之类实盘价差**。
- `reference_sample()`（`#紫卡全面 样例`）是**版式复刻夹具**：`sample=True`，卡脚注与数据源均明确标「版式样例·非实时数据」，仅用于像素对齐回归与显式预览，绝不冒充真实查询。

## 4. 没验证到的 / 已知限制

- **全量 `pytest` 回归未能跑**：本 worktree 缺部署期才有的 `qq_bridge.connector` / `qq_bridge.session` 等模块，`qq_bridge/tests/test_pic_*.py` 等存量用例在**收集阶段**即失败（与本次改动无关，任何改动前都一样）。已在隔离夹具 + 真实 `pic/__init__.py` 加载两个层面补了可跑的验证；真机 E2E 需在部署环境发 `#紫卡全面 样例` 与截图确认。
- **字形差异**：参考卡字体与本机微软雅黑不同，字号按墨迹宽度反推后位置对齐（≤6px），但单个字形轮廓不可能逐像素相同。
- **背景**：按用户要求「除了背景」，未复刻粉色兔纹底图；MOD 缩略卡 / Q 版插画作为前景内容保留。
- **配卡 MOD 图**：参考卡 8 张缩略图取自用户参考卡；真实武器名路径若本地配卡库无图，模板画深色占位卡框 + 真实 MOD 名，不编造图片。
